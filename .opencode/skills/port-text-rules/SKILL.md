# Перенос текстовых разделов core_rules в вики

## Расположение файлов (пути от корня репозитория bc-rag)

- Словарь терминов: `.opencode/skills/wh40k-to-fantasy/dictionary.yaml`
- Очередь переноса: `.opencode/skills/port-text-rules/porting_map.yaml`
- Исходные текстовые правила: `data/core_rules/*.md`
- Целевая вики: `../pathfinder-crusade-wiki/`
- Скрипт точечного поиска раздела:
  `uv run python .opencode/skills/port-text-rules/scripts/find_section.py <core_md_path> <heading_query>`

**Скрипт запускать ТОЛЬКО через `uv run python`** — обычный `python` на PATH не видит зависимости uv-окружения.

## Жёсткие правила
- **НИКОГДА не редактировать файлы в `data/core_rules/`** — это read-only снимок исходной книги, эталон для сверки.
- Переносить только в файлы вики (`../pathfinder-crusade-wiki/`), никогда не в обратную сторону.
- Не переписывать существующий контент вики без явной команды — только **добавлять** недостающее. Если раздел с тем же заголовком уже есть — расширить его, а не дублировать, или пропустить, если он уже полный.
- Никогда не создавать новые целевые файлы вики самостоятельно на своё усмотрение — все целевые файлы либо уже существуют, либо создаются человеком.
- Агент никогда не выполняет `git commit`. Изменения остаются в рабочем дереве для ручного просмотра.
- **Перенос строки внутри блока (не новый абзац) оформляется двумя пробелами в конце строки перед `\n`** (markdown hard break) — так оформлена вся вики. Простой `\n` схлопывается рендерером в один абзац.

## Шаги

1. Открыть `porting_map.yaml`, найти запись со статусом `not_started` для нужного файла (или создать новую, если её ещё нет).
2. Через `scripts/find_section.py` вытащить точный раздел(ы) из `data/core_rules/*.md` по `source_headings`.
3. Адаптировать текст:
   - заменить термины по `../wh40k-to-fantasy/dictionary.yaml` (инвариантные — точной заменой, склоняемые — с согласованием падежа/числа по контексту);
   - сохранить структуру: таблицы, разбивку на навыки/таланты/трейты как в оригинале; если в целевом файле уже есть похожая структура — влиться в неё, не создавать вторую такую же секцию.
4. Вставить адаптированный текст в целевой файл вики на подходящее место.
5. Проверить на Chaos/Imperium-маркеры: прямые упоминания Chaos-богов, ритуальную атрибутику поклонения, механику Cor (Порча), глубокий Imperium-лор (примархи, конкретные организации, техно-физиология). При обнаружении — не пытаться самостоятельно "нейтрализовать", а оставить лучший вариант адаптации и добавить `#Review` с кратким пояснением, что именно нужно перепроверить человеку.
6. Обновить статус записи в `porting_map.yaml` на `done` или `needs_review`.
7. Оставить изменения незакоммиченными — коммит делает человек вручную, после просмотра diff.

### Когда НЕ переносить автоматически
Разделы, целиком завязанные на технологический/sci-fi лор Warhammer 40k без фэнтезийного аналога (импланты, стармтруперская техника и т.п.) — помечать в `porting_map.yaml` статусом `needs_review` с заметкой в `notes`, не переносить вслепую.
