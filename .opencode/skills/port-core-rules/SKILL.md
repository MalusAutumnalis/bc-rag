# Перенос контента из core_rules в вики

## Жёсткие правила
- **НИКОГДА не редактировать файлы в `data/core_rules/`** — это read-only
  снимок исходной книги правил, эталон для сверки.
- Переносить только в файлы вики (`../pathfinder-crusade-wiki/`), никогда не
  в обратную сторону.
- Не переписывать существующий контент вики без явной команды — только
  **добавлять** недостающее из core_rules. Если в вики уже есть раздел с
  тем же заголовком — не дублировать, а расширить его или пропустить,
  если он уже полный.

## Порядок работы
1. Открыть `porting_map.yaml`, найти запись со статусом `not_started`
   для нужного файла (или создать новую запись, если её ещё нет).
2. Через `scripts/find_section.py` вытащить точный раздел(ы) из
   `data/core_rules/*.md` по `source_headings`.
3. Адаптировать текст:
   - заменить термины по `dictionary.yaml` (инвариантные — точной заменой,
     склоняемые — с согласованием падежа/числа по контексту);
   - сохранить структуру: таблицы, разбивку на навыки/таланты/трейты как
     в оригинале, если в целевом файле уже есть похожая структура — влиться
     в неё, а не создавать вторую такую же секцию.
4. Вставить адаптированный текст в целевой файл вики на подходящее место
   (обычно — под существующий заголовок раздела, которого не хватает,
   например `##### Стартовые Навыки:` если в файле пока только Трейты).
5. Если при адаптации встретился текст, слишком специфичный для
   Warhammer-лора (см. правило #Review из скилла wh40k-to-fantasy) —
   перенести с пометкой `#Review` и коротким пояснением.
6. Обновить статус записи в `porting_map.yaml` на `done` или
   `needs_review`.
7. Закоммитить **только один перенесённый раздел за коммит**:
   `git add <файл>; git commit -m "port: <заголовок> from core rules"`.
   Это даёт откатываемые атомарные изменения — если перенос конкретного
   раздела окажется неудачным, откатить можно точечно.

## Когда НЕ переносить автоматически
- Разделы, целиком завязанные на технологический/sci-fi лор Warhammer
  40k без фэнтезийного аналога (импланты, стармтруперская техника и т.п.)
  — такие разделы помечать в `porting_map.yaml` статусом `needs_review`
  с заметкой в `notes`, не переносить вслепую.
